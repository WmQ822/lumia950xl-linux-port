## 二、今日三个关键成果

### ★1. 地址可达性「明暗地图」（v30）
```
✅ 0xFD900000 (MDSS_MDP) = 0x10090000
✅ 0xFDB00000 (GPU kgsl) = 0x00010011
❌ 0xFD9CC000 (MMU0/MDP)  ❌ 0xFDA44000 (MMU1)  ❌ 0xFDA64000 (MMU2)
❌ 0xFDB10000 (MMU3/GPU)  ❌ 0xFDC84000 (MMU4/venus)
❌ 0xFC478000 (MMSS NoC)
```
→ **不是 GPU 专属问题**：**所有 IOMMU（MMU0~4）+ MMSS NoC 整片都暗**，
MDSS/GPU 本体亮（它们在别的路径上）。
⇒ **根因收敛为「MMSS NoC 没通」**，IOMMU 们都"住"在它后面。

### ★2. Windows 的"开机配方"（ACPI/PEP）
PEP 的 ICB/总线配置**来自 ACPI ResourceData**（PEP 字符串含 `src\acpi\Acpi_ResourceData.c`、`ICBID_MASTER_COUNT` 断言）。

**GPU 上电（DSDT `FSTATE 2 / ENTER`）**：
```
1) CLOCK: oxili_rbbmtimer_clk
2) CLOCK: oxilicx_ahb_clk
3) CLOCK: oxili_gfx3d_clk
4) BUSARB: 0x03, ICBID_MASTER_APPSS_PROC, ICBID_SLAVE_GFX3D_CFG, ib, ab   ← 缺的就是这步
5) PSTATE_SAVE / PSTATE_ADJUST ×2
6) FOOTSWITCH: VDD_OXILI / VDD_OXILICX          ← 我们已做（CX/GX GDSC，PWR_ON=1）
7) REQUIRED_RESOURCE: (1, "/clk/oxili", 0)
（EXIT 逆序，其中 BUSARB ib = 0x11E1A300）
```
**BUSARB 格式**：`Package(0x05){ arbType, "ICBID_MASTER_x", "ICBID_SLAVE_y", ib, ab }`，DSDT 共 **311 条**。
GPU 那条（开）：`0x03, APPSS_PROC → GFX3D_CFG, ib=0x11E1A300(300MB/s), ab=0`。

### ★3. 为什么 AP 直写 mnoc 是"死循环"
mnoc 自身不可达 → 没法用 AP 直写它寄存器去开它端口 → **只能由 RPM 侧来开**（RPM 能访问 NoC）。
⇒ 下一步只剩 **① QoS 直写（赌唤醒）** 或 **② RPM 侧 ICB 投票**。

## 三、关键判断链

1. 显示器（MDSS）能亮、GPU 块能读 → 说明 **SNOC 及大部分外设都在线**
2. 但 **全部 IOMMU + MMSS NoC 一律 external abort** → **单一根因：MMSS NoC 未唤醒**
3. 固件配方表明 GPU 需要 **BUSARB 投票** → 投票的本质是"告诉互连/电源子系统打开这条路"
4. 因为 mnoc 不可达，**AP 侧无法自行开它** → 要么找可直达的写法，要么走 RPM
5. 另一个观察：`fdb10000` 读失败是**可恢复 oops**（非硬复位）→ 迭代成本低，可反复探

## 六、踩过的坑（方法论）

1. **插补丁的锚点会"叠顺序"**：我几次都往同一锚点前塞代码 → 执行顺序与预期不一致，导致
   v27 的危险读跑在 v29 派发之前，把探针线程打死、v29 根本没执行。
   ⇒ 危险读**永远放最后**；派发类逻辑**放最前**。
2. **探针线程会被第一记 abort 打死** → 多地址探测要用**每地址一个 kthread**（v29/v30 的写法）。
3. **`fdb10000` 的 abort 现在是非致命 oops**（不再硬复位）→ 试错成本低。
4. **别把"位含义"想当然**：MMCC 分支寄存器 **bit31 = BRANCH_CLK_OFF（1=关）**，
   日志里 `RUN=0` 其实是"没关=在跑"（我一度读反）。
5. **`bytes`↔`AB`**：`MmMapIoSpace` 参数在反编译里会错乱（别被 Ghidra 的 arg 数误导）。
6. **strings 误报**：`strings` 会把 ARM 代码字节当字符串（`qmuxCTXI…` 就是这么来的）——
   判定要交叉验证（GUID 常量、导入表、反编译才作数）。
7. **MO 探针铁律**（沿用）：必须写持久文件 + fsync；禁止在自旋锁关中断区做文件 IO。
8. **日志顺序**：`probe.log` 是跨启动累积的，分析要看 `[late] ENTER` 分块，别被交错的行序骗了。
