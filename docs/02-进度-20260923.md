# 950XL GPU IOMMU 移植 — 进度与卡点（2026-09-23 夜）

> 环境：CachyOS（`~/lumia-kernel`，内核 5.18.0-rc1，交叉编译 aarch64-linux-gnu-gcc 16.1.0）
> 手机：Lumia 950 XL（MSM8994/骁龙810）；rootfs = 手机 eMMC `/dev/sda43`，挂 `/tmp/r43`；内核 `/boot/vmlinuz-5.18.0-rc1`，DTB = `msm8994-msft-lumia-octagon-cityman.dtb`
> 驱动：`drivers/iommu/arm/arm-smmu/qcom_iommu.c`（`CONFIG_QCOM_IOMMU=y`），asid = ctx节点 `reg/0x1000`

## 今晚做了什么（DT：改在 `msm8994-msft-lumia-octagon.dtsi` 末尾追加 &soc/&gpu 覆盖）

| 版本 | 改动 | 现象 | 结论 |
|---|---|---|---|
| v1 | 加 `gpu_iommu`(含 `reg=<0xfdb10000 0x10000>`) + `gpu.iommus=<&gpu_iommu 8>,<&gpu_iommu 9>` | iommu 设备 probe 到（`iommu sec: pgtable size: 151552`），但 3 个 ctx 全 `can't request region... -16 EBUSY`；clk `oxili_gfx3d_clk stuck at 'off'` WARN；adreno attach oops（ctxs[] 为 NULL） | **父 reg 占满 0x10000 → 与子 ctx 区间重叠**。msm8916 的 gpu_iommu 故意不写 reg |
| v2 | **删掉 reg** | ctx 能进 probe，但 `qcom_iommu_ctx_probe` 触发 **synchronous external abort** → panic | 删 reg 对；暴露真正的时钟问题 |
| v3 | 补 `power-domains = CX + GX` | 仍 `oxili_gfx3d_clk` 起不来；`Failed to enable clk '(null)': -16`；ctx_probe 外部中止 | 电源域方向对，但时机不对 |
| v4 | 删 secure ctx（只留 2 个 ns ctx，对齐 msm8916） | 同上（时钟仍起不来） | secure ctx 非主因 |
| v5 | **内核补丁**：`qcom_iommu_device_probe` 里 `pm_runtime_get_sync` 失败→`-EPROBE_DEFER` | 变 **`Asynchronous SError Interrupt` panic**（~10.8s；LUMIA-PROBE 显示 gx/cx GDSC bare write 后即崩；trace 落在 `qcom_iommu_ctx_probe`） | 补丁未达目的；崩点前移到 GDSC/clk 上电路径 |

## 当前判断（核心矛盾）
- GPU IOMMU 在 MMSS 的 **GX/CX 域**；`oxili_gfx3d_clk` 要 GX 有电才能起
- **iommu 是内置(=y)，~10s 就 probe**；而那会儿 RPM 稳压器还在 `-517`、GX 电源没就绪
- 结果：clk enable 失败(-EBUSY) → 硬件没时钟 → 访问 `0xfdb18000` → **外部中止** → oops/panic
- 这已不是"DT 数据错"，而是**时机/电源就绪**问题；进入内核 bring-up 范畴
